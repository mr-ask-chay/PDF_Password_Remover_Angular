Privacy Policy — PDF Password Remover

This page explains what happens to your PDF, its password and other information when you use this site. It describes how the site works today.

No account needed Passwords not stored HTTPS only

In short

  • • PDFs are unlocked on our server, not in your browser.
  • • Your PDF, its filename and its password are sent to the server over HTTPS to do this.
  • • Our application does not save your PDF, filename or password, and does not write them to its logs.
  • • The site uses Google AdSense and Google Fonts, which have their own privacy practices.

How a PDF is unlocked

  1. You choose a PDF and enter its password. Nothing is sent until you select Remove Password.
  2. Your browser requests a short-lived request token from our processing server, then uploads the PDF (including its filename) and the password over HTTPS.
  3. The server opens the PDF with your password in memory, in a separate worker process, and creates an unprotected copy. Our code does not save the PDF to disk. Like most web servers, the web framework may temporarily buffer a large upload in a temporary file while the request is being handled.
  4. The unlocked PDF is sent back to your browser, which keeps it in memory until you download it, unlock another file or leave the page.

What our application does not do

  • It does not save your PDF or the unlocked copy.
  • It does not store your password or write it to its logs.
  • It does not log your PDF’s filename or contents.
  • It does not require an account.
  • It does not use analytics tools.

If an unexpected error occurs, the server records a technical error message to help us fix the problem. This message does not include your password or filename.

Server and hosting logs

This website is hosted by Vercel and the processing server by Render. Like most web services, their request logs can record technical information such as your IP address, browser type, the address requested and the time. Those logs are kept under each provider’s own retention policies.

Stored in your browser

  • Your light/dark theme choice (localStorage).
  • On the API docs page, API keys you create — including the API secret — are saved in your browser’s localStorage so you can see them later. They stay there until you delete them or clear your browser data. Avoid creating keys on shared computers.

Developer API keys

When you create an API key, our server stores the key, an encrypted copy of its secret, the label you chose, when it was created and a daily count of API calls (used for the daily limit). Deleting a key on the API docs page deactivates it. PDFs sent through the API are processed the same way as on the website.

Privacy FAQ

Is my PDF processed in my browser?

Not currently. The PDF is uploaded to our processing server over HTTPS, unlocked there and sent back to you.

Do you keep a copy of my PDF?

Our application does not save your PDF or the unlocked copy. It is held in server memory only while your request is processed.

Do you store my password?

No. Our application uses it only to open your PDF during the request and does not save it or write it to its logs.
